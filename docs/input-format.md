# 入力形式

## 特性関数のベクトル

特性関数は長さ `2^n - 1` のベクトルで与える (空提携を除く)。並び順は 2 種類に対応する。

| 並び順 | 提携 `S` の位置 | 対応する既存実装 |
|---|---|---|
| ビット順 (既定) | `sum_{i in S} 2^i` 番目 (1 始まり) | BNF 実装 (blrzsvrzs/nucleolus) の `v.txt`、TUGLab の `binary = TRUE` |
| 辞書式順 (CLI は `--lex`、ライブラリは `ExplicitGame::from_lex`) | 大きさの昇順、同じ大きさ内は辞書式 | CoopGame、TUGLab の既定 |

プレイヤーは 0 始まりの番号 `0, 1, ..., n-1` で表す。3 人ゲームなら、次の順に書く。

- ビット順: `{0},{1},{0,1},{2},{0,2},{1,2},{0,1,2}`
- 辞書式順: `{0},{1},{2},{0,1},{0,2},{1,2},{0,1,2}`

ファイルは 1 行 1 値のテキストで、空行と `#` で始まる行は無視する。
先頭の UTF-8 の BOM (表計算ソフトやエディタが付けることがある) も無視する。
配分のファイル (`sol.txt`) も同じ形式で読む (配分は、どのコマンドでも最も近い浮動小数点数として読む)。

### 値の書き方

値は 10 進数 (`6`、`-2.5`、`.5`、`1.5e3`) か、`8/3` の形の分数で書く。
符号 (`+`・`-`) は数の先頭 (分数では分子と分母の先頭、指数では `e` の直後) に 1 つまで付けられる。
桁は ASCII の数字だけで、`1_000` のような区切りは書けない。
値の前後と `/` の前後の空白は無視する。

| 字面 | 読み方 |
|---|---|
| `2.5`、`5.`、`.5`、`-1.5e-3`、`2E3` | 10 進数 (書き方は Rust の `f64` の読み取りと同じ) |
| `8/3`、`-1/2`、`1/-2`、`1 / 2` | 分数 (分母が 0 ならエラー) |
| `.-5`、`1.+5`、`+-1`、`1_0`、`1/2_0` | エラー |

ゲームの値の 10 進数は、`nucleolus --exact` と `certify --rational` では字面どおりの有理数 (`0.1` は `1/10`) として、他では最も近い浮動小数点数として読む。
分数は、浮動小数点数として読むときも最も近い浮動小数点数にする。
有理数として読むときは `inf`・`nan` を受け付けず、指数の絶対値は 4096 まで (`game::exact::MAX_DECIMAL_EXPONENT`) とする。

## 費用ゲーム

費用 `c(S)` を与えるゲームは、ライブラリでは `games::cost::CostGame`、CLI では `--cost` で扱う。
節約ゲームに直して解き、費用の分担に戻す。
CLI で費用を扱えるのは `nucleolus` (`--exact` を含む)・`least-core`・`kernel`・`shapley`・`banzhaf`・`compare`。
JSON・CSV の `type` が `cost` のファイルは `--cost` なしでも費用として読み、他のコマンドではエラーにする。
`type` が `value` の JSON と見出しが `coalition,value` の CSV に `--cost` を付けるとエラーにする (`type` を省いた JSON には付けられる)。
ライブラリでは `io::declared_kind_by_extension` で、種類を明示したか (`type` を省いたか) を確かめられる。

## 提携ごとの値の形式 (JSON・CSV)

拡張子が `.json`・`.csv` のファイルは、提携ごとの値で読む。
提携はメンバーのプレイヤーの番号 (0 始まり) で書く。
ライブラリでは feature `io` を有効にして `io` モジュールを使う。

JSON の `values` は、キーが提携 (番号をカンマでつなぐ。順序と空白は問わない) のオブジェクトで書く。

```json
{"players": 3, "type": "value",
 "values": {"0": 0, "1": 0, "2": 0, "0,1": 4, "0,2": 3, "1,2": 2, "0,1,2": 6}}
```

`{"coalition": [番号, ...], "value": 値}` の配列でもよい。
`players` (人数) を省くと、現れた最大の番号 + 1 人とする。
`type` は文字列 `"value"` か `"cost"` で書く。
これ以外のトップレベルのキーは無視する (説明などを書き添えてよい)。
ただし `"tpye"` や `"Players"` のように、`players`・`type`・`values` の書き間違いらしいキー (大文字小文字の違い、1 文字の違い、隣り合う 2 文字の入れ替え) はエラーにする。
`kind` (Python の `parse_game`・`partial_nucleolus` が値の種類を返す名前) も、`type` の書き間違いとしてエラーにする。
配列の要素も同じく、`coalition`・`value` 以外のキーは無視し、`"vlaue"` のような書き間違いらしいキーはエラーにする。
同じオブジェクトの中で同じキーを 2 回書くと、後の値で上書きせずにエラーにする。

```json
{"type": "cost",
 "values": [{"coalition": [0], "value": 4}, {"coalition": [1], "value": 5}, {"coalition": [0, 1], "value": 7}]}
```

CSV は 1 行目を見出し `coalition,value` とし、提携の番号を `|` でつなぐ。
人数は現れた最大の番号 + 1 とする。
値は `8/3` の形の分数でもよい。
先頭の UTF-8 の BOM (表計算ソフトが付けることがある) は無視する。

```csv
coalition,value
0,0
1,0
2,0
0|1,4
0|2,3
1|2,2
0|1|2,6
```

JSON と CSV のどちらでも、次の書き方はエラーにする (CSV のエラーには行番号が付く)。

- 同じ提携の値を 2 回書く。`"0,1"` と `"1,0"`、`0|1` と `1|0` のように順序だけが違う書き方も同じ提携である。
- 1 つの提携の中で同じ番号を 2 回書く (`0|0`、`"0,0"`、`[0, 0]`)。`0|1` の打ち間違いかもしれないので、`{0}` とは読まない。
- 範囲外の番号を書く。`players` を書いたときは `players` 以上の番号、省いたとき (CSV は常に省く) は 63 以上の番号 (人数は 63 人まで)。

全体提携の値がない入力もエラーにする。
番号を 1 始まりで書くと (3 人で `1`・`2`・`3`・…・`1|2|3`)、人数を省いた入力では 4 人のゲームとして読み、全体提携 `{0, 1, 2, 3}` の値がないエラーになる。
番号 0 がどの提携にも現れないときは、このエラーと範囲外の番号のエラーに「プレイヤー番号は 0 始まり」という案内を添える。

CLI の `--lex` は 1 行 1 値のファイルの並び順の指定なので、JSON・CSV の入力に付けるとエラーにする。
逆に `--missing` は JSON・CSV だけの指定なので、1 行 1 値のファイルに付けるとエラーにする。

CLI は `v.txt` と同じく、配分を 1 行 1 値 (`i` 行目がプレイヤー `i`) で出す。
`type` が `cost` (CSV は見出しが `coalition,cost`) なら費用の分担を出す。
`nucleolus --exact` と `certify --rational` は、JSON の数を字面どおり (`0.1` は `1/10`) の有理数として読み、浮動小数点数を経由しない。

```console
$ coopgame nucleolus game.csv
time=0.000077s lp_solves=3 rows_added=0 solver=lp tolerance=6e-7 refinements=0 guarantee=exact levels=[-1.0]
3
2
1
$ coopgame nucleolus cost.json
time=0.000038s lp_solves=2 rows_added=0 solver=lp tolerance=2e-7 refinements=0 guarantee=exact levels=[-1.0]
3
4
```

### 値が分からない提携

値が分からない提携があると、既定ではエラーにして一覧を示す。
CLI では次のオプションで扱いを変えられる。

| オプション | 扱い |
|---|---|
| `--missing zero` | 0 とみなす。費用のゲームでは費用 0 とみなす (下の注意) |
| `--missing ignore` (`--exact` なしの `nucleolus` のみ) | 値が分かる提携だけで解く。1 人提携とその補集合の値は必要。結果の保証は `approximate`。費用なら節約ゲームに直して解く。`--full` は使えない。全提携の表を作らないので、31 人以上 (63 人まで) のゲームも解ける |

費用のゲームで `--missing zero` を使うと、値が分からない提携 `S` の費用を `c(S) = 0` とみなす。
節約ゲームでは `s(S) = sum_{i in S} c({i}) - c(S)` が 1 人提携の費用の和になり、費用が非負なら節約として最大の値になる。
分からない提携が「一緒に行えば費用がかからない」とみなされるので、費用の分担が大きく変わることがある。
真の費用の見積もりがあれば値を書き、なければ `--missing ignore` で分かる提携だけで解くことを検討する。

`{0, 2}` と `{1, 2}` の値がない `partial.csv` の例:

```csv
coalition,value
0,0
1,0
2,0
0|1,4
0|1|2,6
```

```console
$ coopgame nucleolus partial.csv
エラー: partial.csv: 引数が不正: 値が分からない提携が 2 個ある: {0, 2} {1, 2} (--missing zero で 0 とみなすか、--missing ignore で値が分かる提携だけで解く)
$ coopgame nucleolus partial.csv --missing zero
time=0.000109s lp_solves=5 rows_added=0 solver=lp tolerance=6e-7 refinements=0 guarantee=exact levels=[-1.0, -2.5]
2.5
2.5
1
```
